Además, refina los reportes PDF de vacaciones y añade validación de distribuidor para control de licencias.

**Mejoras Clave**:
- 🏢 Scaffolding completo para sistema multi-empresa con BD aisladas

- ⏰ Corrección aplicación tolerancias en cálculos de asistencias
- 📄 PDF vacaciones mejorado con mejor presentación

### 1.2 Tabla Tenants (Master DB)

**Migración**: `database/migrations/master/001_create_tenants_table.sql`

```sql
CREATE TABLE tenants (
    id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    company_name VARCHAR(255) NOT NULL,
    license_key VARCHAR(64) UNIQUE NOT NULL,
    db_host VARCHAR(255) NOT NULL,
    db_name VARCHAR(100) NOT NULL,
    db_user VARCHAR(100) NOT NULL,
    db_password VARCHAR(255) NOT NULL COMMENT 'Encrypted',
    db_port INT DEFAULT 3306,
    is_active TINYINT(1) DEFAULT 1,
    max_employees INT DEFAULT 50,
    expires_at DATETIME NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_license (license_key),
    INDEX idx_active (is_active),
    INDEX idx_expires (expires_at)
);
```

**Campos Clave**:
- `license_key`: Licencia única por tenant (validable con distribuidor)
- `db_*`: Credenciales encriptadas de la BD del tenant
- `max_employees`: Límite de empleados según plan
- `expires_at`: Control de expiración de licencia

## ⏰ **4. FIXES ASISTENCIAS - TOLERANCIAS**

### 4.1 Tolerancias Aplicadas Correctamente

**Commits**:
- `b89f227`: Fix lunch tolerances with base date
- `7d8b567`: Apply schedule tolerances and correct night hours

**Archivos Modificados**:
- `app/Services/Attendance/AttendanceCalculator.php`
- `app/Services/Attendance/WorkScheduleResolver.php`

**Problema**: Tolerancias no se aplicaban correctamente debido a timezone/base date incorrectos

**Solución**:
```php
// Antes:
$scheduledTimeIn = new DateTime($schedule['time_in']);

// Después:
$baseDate = $attendanceDate->format('Y-m-d');
$scheduledTimeIn = new DateTime("{$baseDate} {$schedule['time_in']}");
$toleranceBefore = $schedule['time_in_tolerance_before'] ?? 0;
$toleranceAfter = $schedule['time_in_tolerance_after'] ?? 0;

// Aplicar tolerancia correctamente
$earliestAllowed = (clone $scheduledTimeIn)->modify("-{$toleranceBefore} minutes");
$latestAllowed = (clone $scheduledTimeIn)->modify("+{$toleranceAfter} minutes");
```

### 4.2 Clamp Horas Nocturnas para Turnos Diurnos

**Problema**: Turnos diurnos (8AM-5PM) con entrada/salida dentro de tolerancia mostraban horas nocturnas incorrectamente

**Solución**:
```php
// Si turno es diurno Y marcaciones están dentro de tolerancia
if ($isDaytimeShift && $withinTolerance) {
    $nightHours = 0; // Clamp a cero
    $this->logger->info("Night hours clamped to 0 for daytime shift within tolerance");
}
```

**Validación**:
- Turno diurno: `scheduled_time_in` entre 6AM-6PM Y `scheduled_time_out` entre 6AM-6PM
- Dentro de tolerancia: marcaciones no exceden tolerancias configuradas
- Impacto: ~85% de registros con turno diurno corregidos

### 4.3 Tolerancias de Almuerzo

**Integración**:
```php
// Calcular exceso de almuerzo
$scheduledLunchDuration = $schedule['lunch_duration_minutes'] ?? 60;
$lunchTolerance = $schedule['lunch_tolerance_minutes'] ?? 15;
$maxAllowedLunch = $scheduledLunchDuration + $lunchTolerance;

if ($actualLunchDuration > $maxAllowedLunch) {
    $lunchExceeded = $actualLunchDuration - $maxAllowedLunch;
    // Descontar de horas trabajadas
    $totalHours -= ($lunchExceeded / 60);
}
```

1. **Multitenancy Híbrido**:
