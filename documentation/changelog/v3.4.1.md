## **Componentes Implementados**

### **1. Migración Cálculos de Asistencias**
**Archivo**: `database/migrations/2025_10_10_attendance_calculations.sql` (145 líneas)

#### *Tabla `attendance_calculations`*

Almacena resultados de cálculos procesados de asistencias con métricas detalladas.

**Campos Principales**:
- **Referencias**: attendance_id, employee_id, schedule_id con foreign keys
- **Marcaciones**: time_in, time_out, scheduled_time_in, scheduled_time_out
- **Horas Trabajadas**:
  - total_hours, regular_hours
  - overtime_hours, overtime_25_hours, overtime_50_hours
  - night_hours (6PM-6AM)
  - holiday_hours (feriados/domingos)
- **Tardanzas y Ausencias**:
  - tardiness_minutes, is_late
  - early_departure_minutes
  - is_absent, absence_type (JUSTIFIED/UNJUSTIFIED/UNKNOWN)
- **Tipo de Día**: is_working_day, is_holiday, is_weekend, day_type
- **Métricas**:
  - is_perfect_attendance (sin tardanzas)
  - punctuality_score (0-100)
- **Almuerzo**: lunch_time_minutes (descuento automático)
- **Auditoría**: calculation_version, calculated_at, recalculated_at
- **Detalles**: notes (TEXT), calculation_details (JSON)

**Índices**:
- `unique_attendance_calc` (attendance_id)
- `idx_employee_date` (employee_id, date)
- `idx_date`, `idx_is_late`, `idx_is_absent`
- `idx_is_holiday`, `idx_overtime`, `idx_calculated_at`

---

#### *Tabla `attendance_absence_log`*

Registro de ausencias detectadas con sistema de justificaciones y resolución.

**Campos Principales**:
- **Referencias**: employee_id con foreign key
- **Ausencia**:
  - absence_date, absence_type (JUSTIFIED/UNJUSTIFIED/PENDING)
- **Justificación**:
  - justified (TINYINT)
  - justification_type (MEDICAL/PERMISSION/VACATION/OTHER)
  - justification_document (ruta archivo)
  - justification_notes (TEXT)
- **Día**: is_working_day, day_type
- **Detección**:
  - detected_at (timestamp)
  - detection_method (AUTO/MANUAL/SYNC)
- **Resolución**:
  - resolved (TINYINT)
  - resolved_at (timestamp)
  - resolved_by (FK users)

**Índices**:
- `unique_employee_absence` (employee_id, absence_date)
- `idx_absence_date`, `idx_absence_type`
- `idx_justified`, `idx_resolved`, `idx_detected_at`

### **2. Migración Salarios Múltiples por Tipo de Planilla**
**Archivo**: `database/migrations/2025_10_10_employee_payroll_salaries.sql` (153 líneas)

#### *Tabla `employee_payroll_salaries`*

Sistema de salarios diferenciados por tipo de planilla con histórico de vigencias.

**Objetivo**: Permitir que empleados tengan salarios diferentes según el tipo de planilla (ej: Quincenal vs Mensual).

**Campos Principales**:
- **Referencias**: employee_id, tipo_planilla_id (Foreign Keys)
- **Salarios**:
  - sueldo_base (DECIMAL 10,2)
  - gastos_representacion (DECIMAL 10,2)
- **Vigencia**:
  - fecha_inicio (DATE NOT NULL)
  - fecha_fin (DATE NULL - NULL = indefinido)
- **Estado**: is_active (TINYINT)
- **Auditoría**:
  - created_by, updated_by (FK users)
  - notes (TEXT)

**Constraint Único**:
- `unique_employee_payroll_active` (employee_id + tipo_planilla_id + is_active + fecha_fin)

**Índices**:
- `idx_employee`, `idx_tipo_planilla`, `idx_active`
- `idx_vigencia` (fecha_inicio, fecha_fin)
- `idx_employee_tipo` (employee_id, tipo_planilla_id)

---

#### *Script de Migración de Datos Existentes*

Migración automática de salarios desde sistema legacy:

**Proceso**:
1. Crea tabla temporal para descomponer campo `tipo_planilla_id` (valores separados por comas)
2. Soporta hasta 10 tipos de planilla por empleado
3. Extrae datos usando `SUBSTRING_INDEX()` para parsear valores separados por comas
4. Usa `COALESCE(employees.sueldo_individual, posiciones.sueldo)` para obtener salario
5. `INSERT ON DUPLICATE KEY UPDATE` para evitar duplicados
6. Genera reportes automáticos:
   - Empleados sin salarios configurados
   - Estadísticas por tipo de planilla (promedio, mínimo, máximo)

**Validaciones**:
- Solo migra registros con `sueldo > 0`
- Verifica `tipo_planilla_id NOT NULL`
- Omite valores vacíos o inválidos
