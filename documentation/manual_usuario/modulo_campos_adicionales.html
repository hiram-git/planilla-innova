Módulo de Campos Adicionales Personalizados v3.5.19

Gestión de campos dinámicos personalizados por empleado.

1. ¿Qué son los Campos Adicionales?

Sistema que permite crear campos personalizados para almacenar información específica de cada empleado que no está contemplada en los campos estándar del sistema.

Ejemplo de uso: Número de licencia de conducir, talla de uniforme, grupo sanguíneo, contacto de emergencia, certificación especial, etc.

2. Tipos de Campos Disponibles

TipoDescripciónEjemplo
TEXTOCadena de texto libreLicencia de conducir, contacto emergencia
NUMEROValores numéricos (enteros o decimales)Número de hijos, años de experiencia
FECHAFechas en formato calendarioVencimiento certificación, próxima evaluación
BOOLEANSí/No (verdadero/falso)¿Tiene vehículo?, ¿Maneja inglés?

3. Crear un Campo Adicional

  1. Ir a Empleados → Campos Adicionales.
  2. Click en + Nuevo Campo.
  3. Complete los campos requeridos:
    • Nombre del campo: Identificador único (ej: "licencia_conducir").
    • Etiqueta: Nombre visible en formularios (ej: "Licencia de Conducir").
    • Tipo de dato: Seleccione TEXTO, NUMERO, FECHA o BOOLEAN.
    • Valor por defecto (opcional): Valor que se asignará automáticamente a nuevos empleados.
    • Obligatorio: Marcar si el campo es requerido.
  4. Guarde el campo. Aparecerá automáticamente en los formularios de creación/edición de empleados.

4. Asignar Valores a Empleados

Los campos adicionales aparecen automáticamente en:

  • Crear Empleado: Sección "Campos Personalizados" al final del formulario.
  • Editar Empleado: Misma sección con valores previamente guardados.

Los valores se guardan automáticamente al guardar el empleado.

5. Administración de Campos

Listado de Campos

Vista principal con tabla de todos los campos personalizados configurados:

  • Búsqueda por nombre o etiqueta
  • Filtrado por tipo de dato
  • Paginación automática (DataTables)

Acciones Disponibles

  • Ver: Muestra detalles completos del campo.
  • Editar: Permite modificar nombre, etiqueta, valor por defecto.
  • Eliminar: Borra el campo (requiere confirmación).
Nota: Al eliminar un campo, se eliminan todos los valores asociados de todos los empleados.

6. Validaciones y Restricciones

ValidaciónDescripción
Nombre únicoNo puede haber dos campos con el mismo nombre interno.
Tipo no modificableUna vez creado, el tipo de dato no se puede cambiar (previene inconsistencias).
Formato fechaCampos tipo FECHA validan formato YYYY-MM-DD automáticamente.
Tipo numéricoCampos tipo NUMERO solo aceptan valores numéricos válidos.
Boolean estrictoCampos tipo BOOLEAN solo aceptan 0/1 o true/false.

8. Checklist de Implementación

  • ✓ Definir qué información adicional necesita capturar.
  • ✓ Seleccionar el tipo de dato correcto para cada campo.
  • ✓ Usar nombres descriptivos sin espacios (use guión bajo: _).
  • ✓ Establecer valores por defecto cuando sea apropiado.
  • ✓ Marcar como obligatorio solo campos críticos.
  • ✓ Capacitar al personal de RRHH sobre los nuevos campos.
  • ✓ Actualizar datos de empleados existentes si es necesario.

9. Buenas Prácticas

  • Nomenclatura clara: Use nombres_con_guion_bajo, en minúsculas.
  • No duplicar información: No cree campos que ya existen en el sistema estándar.
  • Tipos apropiados: Fechas para vencimientos, NUMERO para cantidades, BOOLEAN para Sí/No.
  • Valores por defecto: Útiles para campos con respuesta común (ej: "No" en "¿Tiene vehículo?").
  • Documentación interna: Mantenga un registro de qué representa cada campo adicional.
