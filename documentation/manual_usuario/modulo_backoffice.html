Panel Backoffice

Administración multi-tenant: gestión de empresas, configuración y monitoreo del sistema · v3.5.22

Descripción general

El Panel Backoffice es el acceso de administración del sistema multi-tenant de INNOVA Planillas. Desde aquí, el Super Administrador puede gestionar todas las empresas (tenants) registradas en la plataforma, configurar sus parámetros, monitorear el estado del sistema y realizar operaciones administrativas que no están disponibles dentro del panel de cada empresa individual.
Acceso restringido: este panel es exclusivo para usuarios con rol Super Administrador (is_system_admin = true). Los administradores de empresa normales no tienen acceso a estas funciones.

1. Acceso al Backoffice

  1. Ingresar a la URL del backoffice: /backoffice/login.
  2. Autenticarse con las credenciales de Super Administrador (son independientes de los usuarios de cada empresa).
  3. Al ingresar correctamente se redirige al Dashboard del Backoffice.

El login del backoffice es diferente al login del panel de empresa (/login). No comparten sesión.

2. Dashboard del Backoffice

La pantalla principal muestra un resumen del estado del sistema:

  • Total de empresas (tenants) registradas.
  • Empresas activas vs. inactivas.
  • Últimos accesos por empresa.
  • Alertas del sistema o errores detectados.

3. Gestión de empresas (Tenants)

Desde el backoffice puede administrar cada empresa registrada:

AcciónDescripción
Ver listadoTabla con todas las empresas: nombre, subdominio, estado, base de datos asignada.
Crear empresaWizard para registrar nueva empresa: datos, dominio, tipo de BD (MySQL/PostgreSQL), credenciales.
Editar empresaModificar parámetros de conexión, logo, nombre comercial y estado.
Activar / DesactivarSuspender o reactivar el acceso de una empresa sin eliminar sus datos.
MigracionesEjecutar migraciones pendientes en la base de datos del tenant.

4. Wizard de creación de empresa

Al crear una nueva empresa el sistema guía al administrador paso a paso:

  1. Datos de la empresa: nombre legal, nombre comercial, RUC/identificador fiscal, país.
  2. Configuración de acceso: subdominio o identificador único, logo de la empresa.
  3. Base de datos: seleccionar MySQL o PostgreSQL, ingresar credenciales de conexión y nombre de la base de datos.
  4. Usuario administrador: crear el primer usuario administrador de la empresa (email y contraseña inicial).
  5. Confirmación: el sistema prueba la conexión y ejecuta las migraciones iniciales automáticamente.

5. Soporte multi-base de datos

INNOVA Planillas soporta dos motores de base de datos por tenant:

MotorCuándo usarlo
MySQLInstalaciones estándar en Laragon, XAMPP o servidores Linux con MySQL/MariaDB.
PostgreSQLEmpresas que requieren PostgreSQL por política interna o por integración con otros sistemas.

La configuración de conexión se guarda por tenant y el sistema resuelve automáticamente qué adaptador usar en cada solicitud.

6. Gestión de Super Administradores

  • Los Super Administradores se identifican por el flag is_system_admin = true en la tabla de usuarios del sistema central.
  • Tienen acceso a todas las empresas registradas.
  • Pueden impersonar (entrar como) cualquier empresa para diagnóstico o soporte técnico.
  • Las acciones del Super Admin quedan registradas en el log del sistema para auditoría.

7. Migraciones multi-tenant

Cuando se lanza una actualización del sistema que incluye cambios en la base de datos:

  1. El Super Admin accede a Backoffice → Migraciones.
  2. Se muestra la lista de tenants con el estado de migraciones pendientes.
  3. Puede ejecutar la migración en un tenant individual o en todos a la vez.
  4. El resultado de cada migración (éxito/error) se muestra en pantalla y se guarda en el log.

8. Resolución de problemas frecuentes

ProblemaSolución
Empresa no puede iniciar sesiónVerificar que el tenant esté activo y que las credenciales de BD sean correctas desde el backoffice.
Error de conexión a BD del tenantEditar el tenant y verificar host, puerto, nombre de BD, usuario y contraseña. Usar el botón "Probar Conexión".
Migraciones pendientesEjecutar las migraciones desde Backoffice → Migraciones para ese tenant específico.
Super Admin no puede accederVerificar que el usuario tenga is_system_admin = true en la base de datos central del sistema.

9. Checklist de operación

  • Al crear una empresa nueva, verificar que la conexión a su BD sea exitosa antes de finalizar el wizard.
  • Ejecutar migraciones pendientes antes de notificar al cliente que puede acceder tras una actualización.
  • Nunca compartir las credenciales de Super Admin con administradores de empresa.
  • Revisar periódicamente el log de accesos del backoffice para detectar accesos no autorizados.
